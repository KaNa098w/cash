# Бот скидок для Шымкента

Отдельный Python-проект. Смартфоны, ноутбуки, наушники, процессоры, компьютеры,
бытовая техника. Порог 20%, пауза между циклами проверки — 10 минут. Настройки — `settings.json`.
Уведомления включают фотографию из карточки товара и подпись с ценами и ссылкой.
Если фото отсутствует или Telegram отклоняет его загрузку, приходит текст.
Для подписи длиннее 1024 символов также используется текстовое уведомление.
Фото сохраняется в очереди вместе с сообщением; старая база обновляется автоматически.

## Оформление и кнопка анализа

Новые уведомления: фото, жирный процент скидки, зачёркнутая старая цена,
новая цена, сумма экономии, магазин и Шымкент. Внизу две кнопки:
**📊 Полный анализ** и **🛒 Открыть в магазине**.

Нажатие «Полный анализ» открывает личный чат с ботом со ссылкой на выбранный товар.
При первом обращении пользователь нажимает «Запустить». Анализ отправляется только
в личку, а не в группу. Старые callback-кнопки тоже отправляют отчёт на ID нажавшего
пользователя; если бот ещё не запущен в личке, предлагают переход по ссылке.
В отчёте: последняя сохранённая цена и время проверки, минимум,
максимум, первая цена и изменение от неё, диапазоны по месяцам, число проверок
и фактический период наблюдений за последние 365 дней. Время — Шымкент (UTC+5).
Если данных мало, отчёт это указывает. История только по этому товару в этом
магазине: цены до запуска бота не восстанавливаются, пробелы не заполняются.

Кнопки обрабатываются отдельным потоком во время сбора цен и между проверками;
ждать час после нажатия не нужно. Для этого `run` использует Telegram getUpdates.
Webhook у бота должен быть отключён, одновременно может работать только один
экземпляр. Нажатия в других чатах отклоняются. Для проверки кнопок в реальном
Telegram нужны настроенные токен и чат; автоматические тесты используют имитацию API.
Ранее отправленные сообщения не меняются; кнопки появятся в новых уведомлениях.

## Сравнение магазинов

Кнопка **🏪 Цены в других магазинах** запускает отдельный поиск модели на сайтах
и отвечает в личном чате. Сначала приходит подтверждение, затем результат
(поиск может занимать несколько минут). Повторное нажатие не дублирует уже
выполняющуюся задачу. Поиск не ждёт полного обхода каталогов и работает в отдельном
браузере с копией подтверждённой сессии Шымкента. Текущие профили обхода не блокируются.
Снимки сессий хранятся локально в `data/sessions/`; это служебные файлы, не публикуйте их.
Если у магазина нет доступной сессии нужного города, результат сообщает об этом.

В результате показываются только цены, заново полученные после начала поиска:
магазин, цена, ссылка, время проверки. Старые цены не подставляются вместо
результата нового поиска. Отсутствующие товары и непроверенные регионы исключаются.
Если магазин указал зачёркнутую цену, строка имеет вид:
`💰 старая цена → текущая цена (-35%)`. Старая цена зачёркнута,
текущая цена и процент выделены жирным. При отсутствии старой цены процент не вычисляется.

Сопоставление строгое: одинаковый GTIN при наличии либо нормализованное полное
название с сохранением модели, памяти, цвета, суффиксов и комплектации.
У бытовой техники дополнительно используется точная марка и код модели,
например Hansa BK2705.2N: слова «встраиваемый» и «белый» не мешают найти один код.
Разные
написания могут остаться без совпадения; приблизительно похожие товары не подставляются.
Если магазин недоступен или модель не найдена, это явно указано. Старые записи
без подтверждённого региона становятся доступны после повторного обхода.

## Текущий статус

Это ядро мониторинга с браузерными адаптерами, **не подтверждённый
запуск мониторинга всех шести магазинов**. Расчёт скидки, хранение истории,
очередь отправки и дедупликация покрыты тестами. В Chromium проверены карточки
категорий Sulpak, Shop.kz, Technodom и Evrika. Выбор Шымкента для Sulpak и Shop.kz
сохранён в отдельных профилях браузера. Technodom и Evrika используют ссылки
категорий для Шымкента и дополнительную проверку элемента выбранного города.

Mechta и DNS вернули защиту Cloudflare (403) и при прямом запросе, и в Chromium.
Для Mechta `city_selector` пока не настроен. Бот явно сообщит об ошибке этих магазинов.
CSS-правила их карточек предварительные. Для завершения этих двух адаптеров нужны
проверка выбранного города и карточек в браузере, затем успешный `check` каждого
магазина. Нулевое число распознанных товаров считается ошибкой.

`evrika.com` — правильный адрес «Эврики»; `evrica.com` — другой магазин.
Sulpak при первом запросе показал Алматы даже по адресу с `/shymkent`, поэтому
одного адреса страницы недостаточно для подтверждения региона.

## Установка (PowerShell)

```powershell
cd D:\Programs\pos_cash\cash\discount_bot
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
Copy-Item .env.example .env
```

Создайте бота в Telegram через [BotFather](https://t.me/BotFather).
Запишите токен локально в `.env`, в поле `TELEGRAM_BOT_TOKEN`.
Не публикуйте токен и не добавляйте `.env` в Git.
Отправьте боту `/start` в личном чате либо добавьте его в нужную группу и
отправьте команду `/start@имя_бота`. Затем:

```powershell
.\.venv\Scripts\python.exe bot.py chat-id
```

Скопируйте нужный ID в `TELEGRAM_CHAT_ID` в `.env`. Для канала можно использовать
`@имя_канала`; бот должен иметь право публикации. `chat-id` использует getUpdates;
он не работает одновременно с настроенным webhook.

## Город и магазины

Для каждого магазина запустите `setup`, выберите Шымкент в открытом окне,
закройте список городов и нажмите Enter в терминале:

```powershell
.\.venv\Scripts\python.exe bot.py setup --store sulpak
.\.venv\Scripts\python.exe bot.py check --store sulpak
```

Идентификаторы магазинов: `sulpak`, `shop`, `mechta`, `technodom`, `evrika`, `dns`.
Профили сохраняются отдельно в `data/profiles/`. Используется Chromium из Playwright.
Если сайт требует ручную проверку доступа, выполните её в окне setup.
Обход защиты сайта не реализован.

В `settings.json` у каждого магазина:

- `city_selector`: CSS-селектор **только текущего выбранного города**, а не списка
  городов и не всего заголовка страницы. Если он не подтверждает Шымкент,
  уведомлений из этого магазина не будет.
- `rules`: CSS-селекторы карточки, названия/ссылки, полной текущей и старой цены.
  Рассрочку, бонусы, цены комплектов нельзя использовать вместо цены товара.
- `urls`: можно явно задать страницы нужных категорий. Если список пуст,
  бот ищет их в ссылках каталога по названиям и адресам.
- `enabled`: позволяет временно выключить магазин.

`max_pages_per_store: null` отключает искусственный лимит страниц: бот обходит
все найденные страницы выбранных категорий до исчерпания очереди. Повторные URL
не добавляются в очередь заново. Магазины чередуются по одной странице за круг:
Sulpak → Shop.kz → Mechta → Technodom → Evrika → DNS. Завершённые и недоступные
магазины исключаются из текущего круга; большой каталог не задерживает остальные.
Для активных магазинов сохраняются отдельные браузерные контексты, что увеличивает
расход памяти по сравнению с последовательным обходом. Страницы читаются по очереди.
Категории и ссылки «следующая»
обнаруживаются в HTML, бесконечная прокрутка ограничена несколькими прокрутками.
Проверены отдельные страницы категорий, а не полные каталоги всех магазинов.
Полноту каталога нужно проверить для каждого сайта; при достижении лимита
пишется предупреждение. Цена региона не гарантирует наличие в конкретном магазине:
в уведомлении предлагается уточнить наличие, явно отсутствующие товары исключаются.

## Проверка и запуск

```powershell
.\.venv\Scripts\python.exe -m unittest -v
.\.venv\Scripts\python.exe bot.py check
.\.venv\Scripts\python.exe bot.py test-message
.\.venv\Scripts\python.exe bot.py run
```

`check` показывает найденные скидки в терминале, ничего не отправляет и не меняет
историю цен. Возвращает ненулевой код при ошибке магазина.
`test-message` отправляет одно тестовое сообщение в указанный чат.
`run` сохраняет историю и отправляет уведомления о найденных скидках. После завершения
каждой страницы найденные предложения сразу поступают в Telegram, не дожидаясь
завершения обхода остальных страниц и магазинов. В журнале отображается ход обхода.
После завершения
проверки магазинов выдерживается пауза 10 минут, затем начинается следующий цикл.
Сам обход каталогов занимает дополнительное время, поэтому это не гарантирует
проверку каждого товара раз в 10 минут. Одинаковые предложения повторно не отправляются.

Для Шымкента исключены переходы Sulpak на фильтры с другими городами; пагинация
Sulpak читается также из `data-url`. У Technodom и Evrika проверяется регион
в адресе после перенаправлений. Карточки с явно указанным другим городом исключаются.
Для круглосуточной работы компьютер/сервер должен оставаться включённым.

По умолчанию скидка = `(старая цена магазина − текущая) / старая × 100`.
Это заявленная магазином скидка, а не гарантия исторически лучшей цены.
Для сравнения с предыдущей проверкой установите `baseline: "previous_price"`.
В таком режиме первая проверка собирает базу без уведомлений.

Одинаковый товар по той же цене повторно не отправляется, даже если старая
цена выросла. При новой сниженной цене отправляется новое уведомление.
Ошибки отправки сохраняются в очереди SQLite для следующей попытки.
При аварии между успешной отправкой Telegram и записью результата в SQLite
возможен повтор: Telegram не предоставляет ключ идемпотентности для sendMessage.

```powershell
.\.venv\Scripts\python.exe bot.py status
```

Показывает результат последней проверки каждого магазина; время в выводе — UTC.
При сбое магазина остальные продолжают проверяться, ошибка выводится в терминал.
Токен не используется в логах.

После заполнения `.env` можно запускать двойным щелчком по `start_bot.cmd`.
Не запускайте одновременно несколько экземпляров бота с одними профилями.
