# Приёмка товаров на POS

Раздел открывается через меню кассы → «ПРИЁМКА». Продажная корзина остаётся
отдельной: выбор и сканирование в этом разделе меняют только приёмку.

## Работа кассира

1. Список, фильтры, справочники и детали загружаются с сервера с обычной
   авторизацией POS. Фильтры: поставщик, склад, номер, даты, проведение, оплата.
2. «Новая приёмка»: укажите дату, поставщика и склад. Реквизиты можно свернуть.
   Поставщика можно создать здесь же.
3. Товар добавляется выбором из локального каталога, точным сканированием
   штрихкода/локального штрихкода со стандартным завершением Enter или созданием
   через существующий экран товара. Если точного локального совпадения нет,
   касса проверяет штрихкод на сервере. При недоступном сервере не предлагает
   вслепую создавать потенциальный дубль. Неоднозначный штрихкод требует выбора.
4. Повторный скан увеличивает количество той же строки. Количество,
   закупочная и розничная цена редактируются крупной цифровой клавиатурой.
   Количество поддерживает три знака после точки, цены — два.
5. «Сохранить черновик» создаёт/изменяет документ. «Провести приёмку» — отдельное
   действие. Проведённые товары и реквизиты нельзя редактировать, пока сервер
   не разрешит возврат в черновик. Отказ сервера сохраняет проведённый статус.
6. Оплаты поставщику добавляются, редактируются и удаляются отдельно с выбором
   счёта, суммы, даты и комментария. После записи перечитываются детали и список,
   суммы оплаты и задолженности берутся из ответа сервера.

## Доступ и восстановление

Если активный кассир имеет роль `director`, приёмка работает без запроса
ключа управляющего: запросы записи передают его `user_id`. Роль берётся у
активного пользователя после PIN, сервер должен проверять принадлежность
пользователя POS и его права. Бизнес-ограничения проведения сохраняются.
У остальных кассиров для записей запрашивается ключ управляющего текущего магазина. Он передаётся
только в X-Return-Access-Key, не сохраняется в локальных черновиках/журнале и
скрывается в диагностике. Ключ проверяется сервером; после 401 требуется новый.
Отдельный вход директора не нужен. По выходу из раздела ключ удаляется из памяти.

## Создание товара и сенсорные окна

В приёмке открывается полная карточка: название, основной/внутренний штрихкод,
артикул, категория, единица измерения, закупочная/розничная/оптовая цены и
параметры упаковки. Количество прихода задаётся в документе, а не в карточке.
Закупочная цена из формы переносится в строку приёмки даже если API не вернул
её в карточке товара. Успешное создание не повторяется из-за ошибки локального кэша.

Штрихкод можно вводить обычной клавиатурой или кнопкой экранной клавиатуры.
Цифровой ввод хранит строку и сохраняет ведущие нули; при сохранении требуется
11–13 цифр. Сканирование и редактирование штрихкода не очищают название.
Окна ввода, подтверждений и оплат используют единый сенсорный диалог с
крупными кнопками и закреплённой нижней панелью действий.

Редактируемый локальный черновик изолирован по POS и устройству. После выхода
его можно восстановить. Перед сетевой записью сохраняется маркер операции,
поэтому потеря ответа или перезапуск не вызывают автоматического повтора POST.
Если сервер подтвердил создание, ID документа записывается в локальный
черновик до снятия маркера: восстановление продолжает тот же документ.
Если результат неизвестен, обновите список, проверьте документ/платежи и явно
отметьте результат проверенным. Не создавайте уже существующую оплату повторно.

API реализован по предоставленной инструкции: /organizations/pos/{key}/supplies
относительно базового URL с /api. GET передаёт device_id в query, записи —
в теле. organization_id и store_id клиент не добавляет. Импорт, ЦЭДМ, техкарты
и производство в этот раздел не входят.

Автоматические проверки покрывают HTTP-контракт, права, 204/401/404/422,
потерю ответа, повторный запуск, сохранение ID, точность сканирования,
создание/выбор товара, оплаты и компоновку 800×600, 1024×768, 1366×768.
Настоящие документы и оплаты этими тестами на рабочем сервере не создаются.
