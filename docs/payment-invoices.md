# Счета на оплату

В окне продажи кнопка «Счёт на оплату» открывает выставление счёта. Раздел «СЧЕТА» в меню кассы показывает историю с пагинацией. В верхней панели отдельных кнопок счетов нет.

Покупатель обязателен; нового можно создать только по имени. Банковские реквизиты загружаются из `/bank-accounts`: выбирается `is_default`, иначе первый счёт. При пустом списке выставление блокируется. Срок по умолчанию — семь дней, прошлые даты недоступны.

Перед POST `/invoices` полное тело запроса с `client_invoice_id` сохраняется в отложенном чеке. После сетевой ошибки или перезапуска повтор использует исходный UUID, цены, маркировку и остальные данные. Корзина блокируется до получения результата, обычная оплата такой корзины недоступна. Только однозначная ошибка валидации полей разблокирует исправление; конфликт UUID не сбрасывает сохранённый запрос. Успешное создание очищает только исходную отложку и открывает счёт. Создание не вызывает `/sales` и не изменяет локальные остатки или баланс.

В карточке счёта доступны серверный PDF, скачивание PDF/Excel, передача PDF, отмена неоплаченного счёта. Файлы сохраняются в Downloads с уникальным именем; если каталог недоступен на платформе, используется каталог документов приложения. Оплаченный счёт содержит действие просмотра связанной продажи. Срок проверяется по календарной дате `due_at`, даже если сервер вернул `issued`.

Подтверждение требует открытой смены и явного подтверждения поступления полной суммы. Дата отправляется как `yyyy-MM-dd HH:mm:ss`. До POST `/confirm-payment` сохраняются UUID платежа, дата, смена, кассир и комментарий. Неопределённый результат не меняет этот запрос, включая после перезапуска. Перед действием обновляется серверный статус. После подтверждения запускается sync/pull для обновления продаж, остатков и финансовых данных.

Все запросы используют общий Dio с существующим DeviceIdInterceptor. Содержимое документов не журналируется. Для macOS разрешены исходящие подключения, запись в Downloads и сохранение/передача выбранных пользователем файлов.

Проверки: `flutter test test/features/invoices` — контракт API, device_id, календарный срок, восстановление UUID, блокировка корзины, выбор банка, обработка ошибок и сценарии интерфейса. Реальные банковские переводы тесты не подтверждают.
