# Kaspi Smart POS

В окне оплаты выберите «Безналичный» и банковский счёт с названием `Kaspi`
или `Каспи`, затем нажмите «Оплатить». Касса отправит сумму на терминал и
дождётся подтверждения оплаты QR или картой. Только после успеха Kaspi продажа
передаётся в существующий механизм сохранения/синхронизации и печати чеков.
Для смешанной оплаты отправляется только безналичная часть. Другие счета
работают как прежде. Kaspi принимает целые тенге: сумма с тиынами отклоняется
без округления и без запуска операции.

## Подключение

1. Подключите терминал и компьютер к одной частной локальной сети.
2. На терминале откройте панель главного кассира, включите «Защита интеграции»,
   откройте «Настроить доступ».
3. В кассе откройте «Устройства → Kaspi POS», укажите IP терминала и нажмите
   «Зарегистрировать». На терминале разрешите доступ `Leemon-POS`.
4. «Проверить связь» выполняет запрос статуса несуществующей операции: денег
   не списывает и QR не создаёт. После смены IP повторите регистрацию.

На компьютере, где регистрация уже была выполнена из этой задачи, касса
однократно импортирует `%LOCALAPPDATA%\Leemon\Kaspi\registration.dpapi` вместе
с `connection.json`. Регистрация привязана к пользователю Windows; переноса
секретов в исходники или сборку нет. В приложении ключи хранятся через
`flutter_secure_storage`. API работает по HTTPS на порту 8080 с проверкой
сохранённого отпечатка сертификата терминала при недоверенном сертификате.
Токены обновляются через `/v2/revoke`.

## Обрыв связи и повторные попытки

Корзина и первоначальный запрос продажи сохраняются перед запуском Kaspi.
Журнал `kaspi.payment.<localSaleId>` хранит сумму, `processId`, результат и
чековые данные операции, включая идентификаторы транзакции для сверки.

- Если потерян ответ проверки статуса, нажмите «Оплатить» в той же корзине:
  касса запросит прежний `processId`, не отправляя новую оплату.
- `unknown` уточняется через `/v2/actualize` не чаще одного раза в 10 секунд.
- После подтверждённой отмены/отказа можно повторить оплату или выбрать
  другой способ. Пока результат неизвестен, другие операции Kaspi блокируются.
- Если потерян ответ самого запуска и `processId` не получен, автоматический
  повтор запрещён. Администратор должен сверить историю терминала и сохранённую
  корзину. Не удаляйте журнал, пока не установлен результат списания.
- Ошибка backend после успешного списания не освобождает сохранённый запрос:
  повтор завершения продажи использует прежние идентификаторы без повторного
  списания. Старые сохранённые продажи, созданные до включения этой интеграции,
  не запускают Kaspi автоматически.

Возвраты на терминале выполняются отдельно; эта интеграция добавляет оплату
продаж. Терминал печатает свой платёжный слип (`owncheque=false`), касса
продолжает существующий процесс печати товарного/фискального чека.

Протокол: [официальная инструкция Kaspi](https://guide.kaspi.kz/cdn/content/pay/product/documents/Kaspi%20POS/Smart-POS-Dokymentatsia-po-integratsii.pdf).
