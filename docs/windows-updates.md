# Надёжное обновление Windows-кассы

ZIP-обновление теперь сначала распаковывается и проверяется, пока касса ещё работает. Касса закрывается только после сигнала готовности обновлятора и сохранения корзины. Если не хватает прав или архив неполный, касса остаётся открытой.

Перед заменой файлов сохраняется резервная копия. Замены выполняются через временный файл и переименование. Журнал `.leemon-update/pending.json` остаётся до подтверждённого запуска новой версии. Если новый процесс падает или не подтверждает первый кадр интерфейса за 90 секунд, обновлятор восстанавливает прежние программные файлы и запускает кассу снова. Подтверждение также содержит версию: пакет с неверной версией не считается успешно установленным.

Повторный обычный запуск во время замены файлов показывает сообщение о выполняющемся обновлении. Если питание пропало во время замены и остался журнал, Windows launcher при следующем открытии запускает восстановление перед загрузкой интерфейса. Это работает после установки нового launcher и нового helper; старые установленные версии сами этого не умеют.

Продажи, локальная очередь, SQLite и настройки в профиле пользователя не входят в замену и откат. Восстанавливаются только программные файлы. Откат не является резервной копией базы и не позволяет безопасно отменять несовместимые миграции её структуры: такие миграции нужно отдельно проектировать с обратной совместимостью.

## Выпуск

1. Для перехода со старой версии пакет содержит helper и в корне ZIP, и в папке `updater`. Прежний helper пропускал папку `updater`, но копирует файл из корня. Новая касса использует корневую копию и переносит её во временную папку перед запуском. Поэтому следующий цикл обновления уже использует новый механизм. Первая установка этого пакета прежним helper ещё выполняется по прежним правилам; для уже повреждённой установки используйте полный установщик.
2. Для будущих ZIP-выпусков задайте новую версию в `lib/core/service/app_build_info.dart` и запустите `tools/build-update-package.ps1`.
3. Скрипт собирает helper, собирает Windows-кассу с тем же номером версии, включает helper в ZIP и создаёт JSON с размером и SHA-256. Ничего не публикует на сервер.
4. Пакет и метаданные находятся в `build/update-packages`. На сервере версия, размер и SHA-256 должны соответствовать этому пакету.
5. Перед массовой установкой проверьте обновление на тестовой кассе с типичным объёмом данных. Новые миграции БД должны быть совместимы с предыдущей версией.

Установка EXE остаётся отдельным маршрутом установщика; журнал, проверка запуска и автоматический откат выше относятся к ZIP-маршруту.

## Диагностика

В папке приложения: `.leemon-update/update.log`, `.leemon-update/last-failure.json`, резервные программные файлы в `.leemon-update/backup`.

Версия с неудачным запуском не предлагается автоматически повторно. Ручная проверка обновлений остаётся доступна. Следующий выпуск с другим номером проверяется как обычно.

## Проверки

```powershell
flutter test test/core/service/app_update_lifecycle_test.dart test/features/presentation/pages/products/payment_recovery_test.dart
dotnet run --project test/updater/UpdaterTests.csproj -c Release
```

Подпроцессные тесты используют отдельное тестовое приложение, а не установленную кассу. Они проверяют ожидание закрытия, успешный запуск, раннее падение и зависание без подтверждения запуска. Для них нужно опубликовать тестовый executable и передать пути к helper и этому executable в `UpdaterTests.exe`.
